# שמות קבצים חסרי סיומת — מה תוקן ומה נשאר

מסמך המשך. התיקון קדימה כבר פרוס; מה שמתועד כאן הוא **מה שנשאר לעשות
לקבצים שכבר אוחסנו**, כדי שאפשר יהיה להשלים אותו כשהבדיקות הנוכחיות ייגמרו,
בלי לשחזר את החקירה מחדש.

## הבאג

`_safe_filename` ב‑`app/services/storage_client.py` כיווץ כל רצף לא‑ASCII ל‑`_`
ואז הריץ `.strip("._-")` על שני הקצוות. שם שכולו עברית מתכווץ לקו תחתון בודד,
וה‑strip בלע גם אותו וגם את הנקודה שהפרידה בינו לסיומת:

```
"מעג\"ל מבנים.gpkg"  →  "_.gpkg"  →  strip("._-")  →  "gpkg"
"חופות עצים 2024.gpkg"  →  "_2024.gpkg"  →  "2024.gpkg"
```

לכן זה נראה אקראי: **תו ASCII אחד בכותרת** — ספרה בשנה, מספר בשם — הכריע.

## היקף — נמדד, לא הוערך

סריקה מלאה של כל 866 שכבות ה‑GovMap הפעילות (4.8.2026):

```
856  מחזיקות לפחות קובץ אחד ללא סיומת   (98.8%)
 10  נקיות

לפי סוג הקובץ:   csv 827 · gpkg 18 · geojson 12 · parquet 6
```

הפילוח מסגיר את השורש: **827 מתוך 856 הם ה‑CSV** — כלומר לא הכותרת היא הגורם
העיקרי אלא שם המשאב הקבוע.

והסיבה רחבה מהכותרת. ה‑GPKG וה‑Parquet אכן תלויים בכותרת השכבה — אבל ה‑CSV
נבנה מ‑`f"{res.name}.csv"`, ו‑`res.name` בכל דחיפת סורק הוא הקבוע **"נתוני
הסורק"**, עברי לחלוטין. לכן `נתוני הסורק.csv` → `csv` בכל שכבה, ללא יוצא מן
הכלל. אותו קוד משרת כל מקור סורק, ו‑`snapshot_service` בונה מפתחות מ‑
`f"{res_name}.{ext}"` עם שמות משאבים מ‑CKAN שרובם עבריים — כלומר התופעה חוצה את
כל המאגרים, לא רק את שכבות GovMap.

## מה כבר תוקן (cb4aa97)

1. **קדימה** — הסיומת נחתכת לפני החיטוי, מול רשימת סיומות מוכרות. כל גרסה
   חדשה מקבלת שם תקין (`file.gpkg` במקום `gpkg`). כל שכבה שנסרקת ממילא נרפאת.
2. **היסטורית, במקומות ש‑OVER שולט בשם** — `_filename_from_value` מחזיר
   `data.gpkg` / `data.csv` במקום `gpkg` / `csv`. זה מכסה את הייצוא ל‑Drive
   ואת הממשק, בלי לגעת באחסון.

## מה שנשאר — הפער היחיד

**ההורדה הישירה מהדפדפן, לקבצים שאוחסנו לפני התיקון.** שם הקובץ מגיע ממפתח
ה‑R2 עצמו, וההורדה היא הפניה 307 לדומיין הציבורי — אין לנו דרך להזריק
`Content-Disposition`, ותכונת `download` ב‑HTML מתעלמת ממנה בין־מקורית.

**מה שאסור לעשות:** לסרוק מחדש 866 שכבות בשביל שם קובץ. זה כמה ימי גרידה
ועומס אדיר על GovMap בתמורה לסיומת, והנתונים עצמם תקינים לחלוטין.

**שלוש דרכים אמיתיות, בסדר עלות:**

1. **להמתין** — התיקון קדימה פרוס, וכל סריקה סוגרת שכבה. הרולאאוט הרבעוני
   יסגור את השאר מעצמו. עלות אפס.
2. **דומיין מותאם מול הבאקט** — `S3_PUBLIC_BASE_URL` כבר נתמך בקוד
   (`app/config.py`). דומיין משלנו מול R2 מאפשר `Content-Disposition`, ואז
   **כל 866 נרפאות בבת אחת בלי ולו סריקה אחת**. זו החלטת תשתית (DNS + Cloudflare),
   לא עבודת גרידה. זו ההמלצה אם השם בהורדה חשוב.
3. **לשרת את ההורדה דרך OVER** — עוקף את R2 ומאפשר לקבוע כותרת. נדחה בכוונה
   בעבר: ‎`/api/versions/{id}/download/` מפנה ל‑R2 דווקא כדי שגיגה‑בייטים לא
   יזרמו דרך dyno של 512MB. לא לחזור לזה בלי סיבה טובה.

## איך להשלים כשמגיע הזמן

אם בוחרים באפשרות 1 ורוצים לדעת מה עוד לא נרפא, הסריקה שמייצרת את הרשימה היא
`extension_audit.py` (בתיקיית העבודה של הסשן): לכל מאגר govmap פעיל היא קוראת
את הגרסה האחרונה, מחלצת את זנבות מפתחות ה‑R2, ומדווחת אילו מהם חסרי סיומת
מוכרת. הפלט `extension_audit.json` הוא רשימת המאגרים לתיקון.

הבדיקה הקובעת אחרי כל סבב:

```
tail = key.rsplit("/", 1)[-1]          # אחרי הסרת קידומת ה-rand8
תקין אם tail מסתיים באחת מהסיומות המוכרות
```

## מה שלא צריך לעשות שוב

* לא לשנות מפתחות קיימים. `resource_mappings` וכל קישור שפורסם מצביעים עליהם;
  שינוי שם המפתח שובר הורדות קיימות.
* לא להוסיף עוד טלאי נקודתי כמו ה‑`if name.lower() == "csv"` שהיה שם קודם —
  הוא כוסה והוכלל.
