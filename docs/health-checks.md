# בדיקות מערכת: יומית, שבועית ולפי דרישה

מנגנון אחד שבודק את כל רכיבי המערכת, שומר כל ריצה בלוג, ומציג בטאב **בדיקות מערכת** (`/admin#health`)
מה שבור עכשיו, ממתי, ומה השתנה מאז הבדיקה הקודמת.

קוד: `app/services/health_checks.py` (בדיקות ומריץ), `app/api/admin_health.py` (API),
`frontend/src/components/HealthChecksPanel.tsx` (הטאב), טבלה `app.health_runs` (מיגרציה 074).

## למה

כבר היו חלקים מזה: פאנל הכשלים בתור, פאנל הוורקרים, `/healthz`, ושלושה סקריפטים
(`scripts/api_smoke_test.py`, `api_docs_test.py`, `source_health_check.py`) שצריך לזכור להריץ.
לאף אחד מהם לא הייתה היסטוריה. סקרייפר שנשבר ביום שלישי התגלה כשמישהו במקרה הסתכל,
ואי אפשר היה לדעת אם הוא שבור מאז שלישי או כבר חודש.

**איך מזהים סקרייפר שבור.** שלוש בדיקות משלימות זו את זו:
`scrapers.runs` תופסת סקרייפר שנכשל ברעש. `scrapers.overdue` תופסת מצב שבו המתזמן לא מגיע למאגר.
`scrapers.silent` תופסת סקרייפר שמסיים "בהצלחה" בלי לייצר כלום. `upstream.sources` עוזרת להבדיל בין "המקור נפל" לבין "הסקרייפר שלנו נשבר".
ריצה שנקטעה (ורקר שנסגר באמצע) לא נספרת ככשל, בדיוק כמו בתור הגירוד.

## הלוג וההשוואה בין ריצות

כל ריצה נשמרת ב-`app.health_runs` עם כל התוצאות, ונשמרת 180 יום (`HEALTH_RETENTION_DAYS`).
כל תוצאה, וכל תת-תוצאה (מקור, ורקר, נקודת קצה), מושווית לריצה האחרונה שהריצה את אותה בדיקה:

- **בעיה חדשה**: לא הייתה בריצה הקודמת, או שהחמירה מאזהרה לכשל. מופיעה בלוג עם `+`.
- **נמשכת**: נושאת את `since` מהריצה הראשונה שראתה אותה. בטאב זה מוצג כ"כבר 30 שעות".
- **נפתרה**: הייתה רעה ועכשיו תקינה. מופיעה בלוג עם `✓`.

ריצה שנשארה במצב `running` יותר משעתיים (כי השרת הופעל מחדש באמצעה) נסגרת כ-`error` בריצה הבאה.

## התראות

`HEALTH_ALERT_WEBHOOK_URL` היא כתובת webhook נכנסת (Slack, Discord, Google Chat, או כל מקבל JSON).
נשלחת רק כשיש **בעיות חדשות**, כך שמקור ששבור שבוע לא שולח שבע התראות. הגוף הוא
`{"text": …, "content": …}` ומכיל את רשימת הבעיות החדשות וקישור ל-`/admin#health`.

**מגבלה:** הבדיקות רצות בתוך האפליקציה. אם השרת כולו נופל, אין מי שיתריע.
לכן מומלץ להוסיף ניטור חיצוני חינמי (UptimeRobot, Better Stack, cron-job.org) על `https://over.org.il/healthz`.

## API (אדמין)

```
GET  /api/admin/health/checks      הרשימה, מה כל בדיקה עושה, וההרצות הבאות
GET  /api/admin/health/overview    הממצא האחרון לכל בדיקה והריצה האחרונה מכל סוג
GET  /api/admin/health/runs        הלוג (?tier=&status=&limit=&offset=)
GET  /api/admin/health/runs/{id}   ריצה אחת עם כל התוצאות
POST /api/admin/health/run         {"tier": "daily"|"weekly"} או {"checks": ["scrapers.runs"]}
```

## הוספת בדיקה

```python
@check("my.thing", component="רכיב", title="כותרת", description="מה נבדק",
       tiers=("weekly",), timeout=60)
async def check_my_thing(ctx: Ctx) -> CheckResult:
    async with ctx.session_factory() as db:
        ...
    return CheckResult(OK, "משפט אחד", details={...}, items=[{"key", "label", "status", "message"}])
```

`ctx.deep` מסמן את הריצה השבועית. כדאי להחזיר `items` לכל דבר שאפשר לשבור בנפרד, כי ההשוואה בין ריצות וההתראות עובדות ברמת ה-item.
הבדיקות נבדקות ב-`tests/test_health_checks.py`.
